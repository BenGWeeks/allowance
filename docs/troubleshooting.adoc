= Troubleshooting Guide
:toc:
:toc-placement: preamble
:toclevels: 2

This guide helps you resolve common issues with the LNBits Allowance extension.

== Installation Issues

=== Extension Not Appearing in LNBits

If the Allowance extension doesn't appear in your LNBits extensions list:

. Check the extension is properly installed:
+
[source,bash]
----
ls -la /app/lnbits/extensions/allowance
----

. Verify the extension structure:
+
[source,bash]
----
# Required files must exist:
allowance/
├── __init__.py
├── config.json
├── manifest.json
└── migrations.py
----

. Restart the LNBits container:
+
[source,bash]
----
docker restart lnbits
# or
docker-compose restart
----

. Check container logs for errors:
+
[source,bash]
----
docker logs lnbits 2>&1 | grep -i allowance
----

=== Database Migration Errors

If you see errors related to database tables or columns:

. Check migration status:
+
[source,bash]
----
docker exec lnbits psql -U lnbits -d lnbits -c "SELECT * FROM dbversions WHERE ext = 'allowance';"
----

. If migrations haven't run, restart the container
. If you see column errors like `column 'lnurlpay' does not exist`:
  - This usually means the container is running old code
  - Restart the container to load updated code

== Payment Issues

=== Allowances Not Sending Payments

If scheduled payments aren't being sent:

. Verify the scheduler is running:
+
[source,bash]
----
docker logs lnbits 2>&1 | grep -i "allowance payment scheduler"
----

. Check allowance status:
  - Ensure the allowance is marked as "Active"
  - Verify start_datetime has been reached
  - Check end_datetime hasn't passed

. Check Lightning address validity:
  - Test the Lightning address manually
  - Ensure it accepts the payment amount

. Monitor scheduler logs:
+
[source,bash]
----
docker logs -f lnbits 2>&1 | grep -E "allowance|payment|scheduler"
----

=== Payments Failing with Amount Errors

If you see errors like `value is not a valid integer`:

. Check the amount field:
  - Must be a positive integer for sats
  - Can be decimal for fiat currencies

. Verify currency conversion:
  - Fiat amounts are converted to sats at payment time
  - Ensure currency rates are available

=== Automatic Deactivation

Allowances may be automatically deactivated if:

. The end_datetime is in the past
. Payment failures exceed retry limits
. The wallet balance is insufficient

== Form and UI Issues

=== Datetime Fields Showing Wrong Values

If dates appear incorrect when editing:

. This is often a timezone display issue
. Dates are stored in UTC and converted for display
. The actual stored values are usually correct

To verify:
[source,bash]
----
# Check what's actually stored in the database
docker logs lnbits 2>&1 | grep "Update request"
----

=== Active Toggle Not Persisting

If the Active status doesn't save:

. Check if the allowance has expired:
  - Expired allowances (end_datetime in past) cannot be reactivated
  - The Active toggle will be automatically disabled if end_datetime is in the past
  - Update the end_datetime to a future date first, then the Active toggle will be re-enabled

. Verify the update request succeeds:
  - Check browser console for errors
  - Monitor container logs during save

=== Form Values Not Loading

If edit forms show empty fields:

. Check browser console for JavaScript errors
. Verify the allowance data is loading:
+
[source,javascript]
----
// In browser console:
console.log(window.app.allowances)
----

. Clear browser cache and reload

== API Issues

=== 404 Not Found Errors

If API calls return 404:

. Verify the correct endpoint:
  - Use `/allowance/api/v1/allowance` (singular)
  - Not `/allowance/api/v1/allowances` (plural)

. Check API key validity:
  - Use admin key for write operations
  - Use invoice key for read operations

. Ensure wallet exists and has permissions

=== 500 Internal Server Errors

If API calls return 500 errors:

. Check container logs for detailed error:
+
[source,bash]
----
docker logs lnbits 2>&1 | tail -100 | grep -i error
----

. Common causes:
  - Database connection issues
  - Missing required fields
  - Data type mismatches

== Docker and Container Issues

=== Container Won't Start

If the LNBits container fails to start:

. Check port conflicts:
+
[source,bash]
----
netstat -tlnp | grep 5000
----

. Verify environment variables in `.env`
. Check Docker logs:
+
[source,bash]
----
docker-compose logs lnbits
----

=== Extension Code Not Updating

If changes to the extension aren't reflected:

. The container needs to be restarted:
+
[source,bash]
----
docker-compose restart lnbits
----

. Verify the volume mount is correct:
+
[source,yaml]
----
volumes:
  - ./allowance:/app/lnbits/extensions/allowance
----

. Check file permissions:
+
[source,bash]
----
ls -la allowance/*.py
----

== Database Issues

=== PostgreSQL Connection Errors

If you see database connection errors:

. Verify PostgreSQL is running:
+
[source,bash]
----
docker ps | grep postgres
----

. Check database credentials in `.env`
. Test connection manually:
+
[source,bash]
----
docker exec lnbits psql -U lnbits -d lnbits -c "SELECT 1;"
----

=== Table or Column Doesn't Exist

If you see schema-related errors:

. This usually means migrations haven't run
. Check the migrations.py file exists
. Restart the container to trigger migrations
. For development, you may need to reset migrations:
+
[source,bash]
----
# Reset migration tracking (forces migrations to re-run)
docker exec lnbits-dev python3 -c "import sqlite3; \
  conn = sqlite3.connect('/app/data/database.sqlite3'); \
  conn.execute('DELETE FROM dbversions WHERE db = \"allowance\"'); \
  conn.commit()"

# Remove extension database (CAUTION: deletes all data!)
docker exec lnbits-dev rm -f /app/data/ext_allowance.sqlite3

# Restart to trigger migrations
docker compose restart lnbits-dev
----

**Understanding Migrations:**

* **m001**, **m002**, etc. are migration functions in `migrations.py`
* LNBits runs them in numerical order on extension startup
* The `dbversions` table tracks which migrations have run
* If a migration is modified after running, LNBits won't re-run it
* Solution: Reset dbversions entry or disable/enable the extension

== Testing Issues

=== Playwright Tests Failing

If UI tests fail:

. Ensure LNBits is running and accessible
. Verify test credentials in `.env.local`
. Check for UI changes that broke selectors
. Run tests with visible browser:
+
[source,javascript]
----
// Change headless: true to false in test files
const browser = await chromium.launch({ headless: false });
----

=== API Tests Failing

If API tests fail:

. Verify the test wallet exists
. Check API keys are valid
. Ensure test data doesn't conflict
. Run tests individually to isolate issues

=== File Hash Mismatch During Installation

If you see "File hash mismatch. Will not install" when installing via extensions.json:

. This error occurs when the SHA256 hash in `extensions.json` doesn't match the actual archive file
. The extension uses a tagged release (not main branch) to ensure stable hashes
. If you've just updated to a new version:
  - Uninstall the extension completely
  - Clear cached extension files:
+
[source,bash]
----
docker exec lnbits rm -rf /app/lnbits/extensions/allowance
docker restart lnbits
----
  - Reinstall from the extensions marketplace

. The hash is calculated from the release archive:
+
[source,bash]
----
curl -sL "https://github.com/BenGWeeks/allowance/archive/refs/tags/v1.0.2.zip" | sha256sum
----

. **Why we use tagged releases:** Using `main` branch would cause the hash to change with every commit, making verification impossible. Tagged releases (e.g., v1.0.2) provide immutable snapshots with stable hashes.

== Getting Help

If you can't resolve an issue:

. Check the https://github.com/lnbits/lnbits[LNBits documentation]
. Search for similar issues on https://github.com/BenGWeeks/allowance/issues[GitHub Issues]
. Enable debug logging:
+
[source,bash]
----
export LNBITS_DEBUG=true
docker-compose restart
----

. Collect relevant information:
  - Error messages from browser console
  - Container logs during the error
  - Steps to reproduce the issue

. Create a detailed issue report on GitHub

== Prevention Tips

. Always restart containers after code changes
. Test in development before production
. Keep backups of your database
. Monitor logs regularly:
+
[source,bash]
----
docker logs -f lnbits 2>&1 | grep -i allowance
----

. Use the test suite to verify changes:
+
[source,bash]
----
./tests/run_all_tests.sh
----
