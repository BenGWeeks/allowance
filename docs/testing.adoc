= Testing Allowance

== Offline regression checks

Run from the repository root with Docker available:

[source,bash]
----
docker run --rm --network none \
  -e LNBITS_DATA_FOLDER=/tmp/allowance-tests \
  -e LNBITS_BACKEND_WALLET_CLASS=FakeWallet \
  -e LOGURU_LEVEL=ERROR \
  -v "$PWD:/app/lnbits/extensions/allowance:ro" \
  lnbits/lnbits:v1.6.1 \
  /app/.venv/bin/python /app/lnbits/extensions/allowance/tests/run_unit_tests.py
bash tests/run_postgres_tests.sh
bash tests/run_release_tests.sh
python3 tests/test_release_builder.py
----

The PostgreSQL and release checks use disposable FakeWallet containers and internal Docker networks. Release checks exercise LNbits' native installer, fresh installation, upgrades, cached modules and schema preservation. See link:releasing.md[release preparation] for their scope. CI in `.github/workflows/api-unit-tests.yml` runs regressions and installation checks against the declared minimum, pinned stable and discovered latest stable LNbits versions, plus PostgreSQL and quality checks.

== Browser checks on development

Use a dedicated FakeWallet instance and test account. Complete LNbits onboarding and install/enable Allowance first.

[source,bash]
----
npm ci --prefix tests
cd tests
npx playwright install chromium
cd ..
----

Browser configuration comes from process environment or the repository's private `.env.local`:

[source,text]
----
TEST_LNBITS_URL=https://your-development-instance.example
LNBITS_ADMIN_USERNAME=development-user
LNBITS_ADMIN_PASSWORD=development-password
RECEIVING_WALLET_NAME=Development wallet
PAYLINK_EMAIL=recipient@example.invalid
ALLOWANCE_TEST_CREATE_AMOUNT=100
ALLOWANCE_TEST_EDIT_AMOUNT=200
----

For mutation tests, explicitly set `ALLOWANCE_UI_TEST_CONFIRM` to exactly `TEST_LNBITS_URL`.

[source,bash]
----
./tests/node_modules/.bin/playwright test --config tests/playwright.config.js --workers=1
----

The Playwright spec files test all seven frequencies through creation, editing, persistence and deletion, plus account/wallet prerequisites, currency options, Pay Links integration and payment-history behavior. Allowances stay inactive; these browser tests do not prove recurring payment execution or Lightning settlement. Install and enable Allowance and Pay Links for the configured account before running the full suite. Diagnostic fixtures intercept payment APIs with synthetic responses. UI tests are run separately from offline CI and require their own development instance. Never point them at a live funding wallet.

== Standalone browser commands

The existing `tests/ui/crud/*.js` and `tests/ui/setup/*.js` commands select tests
from the same Playwright suite. They propagate its exit status and close their
browsers through the runner. Run them from any working directory.

[cols="1,2",options="header"]
|===
|Command |Scenario
|`create-allowance`, `read-allowances`, `update-allowance`, `delete-allowance`, `delete-all-test-allowances`
|Complete monthly create/edit/reload/delete lifecycle, including cleanup of only this run's record.
|`create-minutely-allowance`, `create-hourly-allowance`
|The same lifecycle at the named frequency, with an inactive allowance.
|`create-admin-account`, `create-receiving-wallet`
|Verify the initialized account and configured wallet. These commands no longer provision persistent accounts or wallets.
|`install-extension`, `install-allowance-extension`, `enable-allowance`
|Verify that Allowance is installed, accessible and has a healthy scheduler. Native installation/upgrade coverage remains in `tests/run_release_tests.sh`.
|`check-currencies`, `validate-allowance-page`
|Verify the creation dialog and available currency options.
|`install-paylinks-extension`, `enable-paylinks`
|Verify that Pay Links is installed, enabled and accessible with the configured wallet.
|`create-paylink`, `delete-paylink`
|Create a uniquely named pay link, verify persistence, delete it and verify its absence. Never remove a pre-existing link.
|===

`bash tests/run_ui_tests.sh` runs every browser scenario.
`bash tests/run_ui_crud_tests.sh` runs only Allowance CRUD and diagnostic scenarios.
Both fail when assertions, configuration or prerequisites fail. There are no automatic
mutation retries and no text matching of success messages. Missing onboarding,
extensions or wallets fails explicitly; initialize a dedicated development instance
before testing. CI checks syntax and test discovery; authenticated browser execution
remains a separate dev check.

== Manual tools

`tests/api/` includes operational tools that create active allowances, perform cleanup or inspect payments. They are not equivalent to the offline regression runner, and `tests/run_all_tests.sh` does not run every CI check. Inspect a tool and its configured destination before running it. Do not run bulk cleanup against shared development or production data.

== Release validation

Validate the exact release archive on dev, including startup, activation, scheduler heartbeat, archive/source agreement and unchanged schedules. Use synthetic LNURL services to test invoice submission and settlement with FakeWallet. For split DNS, test both a blocked private resolution and an explicitly trusted hostname/IP with HTTPS certificate validation; metadata checks alone do not prove settlement.

No test suite guarantees a working production funding source. After deployment, inspect server health, funding connectivity and the recorded outcome of the next intended payment. Keep credentials, recipient addresses and server logs out of public artifacts; screenshots should use synthetic data.
